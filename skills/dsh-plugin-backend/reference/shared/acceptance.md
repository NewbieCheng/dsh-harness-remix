# 验收：从“能跑”到“能交付”

> 两条铁律：**未在真机看到行为，不写“完成”**；**停用后必须完全恢复原生**。
> 下面的清单按“先问、再做、再验”排列，任何一项没勾都不能说完成。

## 1. 开工前 6 问（答不上就别写代码）

1. 目标 DSH 版本是什么？`dsh --version` 的输出贴出来。
2. 你要动的是**官方某个落座点**，还是**整壳接入**？（决定走槽位还是 iframe/覆盖层）
3. 那个位置是 list 还是 single？有 occupant 吗？（决定“加”还是“换”）
4. 替换/覆盖后，官方原功能是**保留入口**还是**明确移除**？移除要写进交付说明。
5. 失败时怎么回退？有开关吗？开关默认是开还是关？
6. 这次改动落在哪半边：Host、Client、还是两边？（决定构建与生效路径）
7. 这个交互依赖 **OS 拖放 / 剪贴板 / 全局快捷键** 吗？宿主是否以管理员运行（UIPI 会拦掉整个窗口的
   文件拖放）、自建 iframe 是否带 `sandbox`？——拖不动先分层取证，不要先改 handler（见 `CASE-drop-refused.md`）。
