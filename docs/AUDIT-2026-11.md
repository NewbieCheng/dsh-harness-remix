# 审计：v1 两套 skill（2026-11）

> 对象：`dsh-ui-remix`、`dsh-backend-bridge`（仓库 v1，commit `5d367ec`）。
> 目标：回答“这套规范能不能让别的 agent 独立完成插件开发”。结论：**心法可用，事实层需重建**。

## 1. 事实基线

| 项 | v1 实况 | 影响 |
|---|---|---|
| 文件 | 2×SKILL.md + 7 个 reference（仓库里 1420 行） | 内容不算少 |
| 安装 | 装到 `~/.dsh/skills` 的**只有 SKILL.md** | 所有 `reference/` 引用是死链 |
| 槽位数 | 声称 77 | 真机 116 + 13 Factory |
| 基数 | 只讲 single/multi 两档 | 实际 5 档（含 keyed/chain/hoc） |
| 清单层 | 无 | 没有 `dsh.bundle`/`profile`/`engines`，插件发不出去 |
| 后端通道 | 只有 HTTP 路由 | 缺 typert / storageDomain / settings 自动表单 |
| 版本 | 只有“升级后回归”一句 | 无版本矩阵、无生成机制 |

## 2. 五类处置

### 保留（v2 继承）

- 三条铁律（不改本体 / 不手改产物 / 未验证不算完成）；
- 四类改造决策树（替换 / 插入 / 接入 / 主题）；
- 注入范式骨架：`cleanup` + `MutationObserver` + `rAF` 节流 + disposed；
- 生效矩阵、日志脱敏、测试禁真模型。

### 更新（v2 改写）

| 项 | v1 | v2 |
|---|---|---|
| 槽表 | 手写 77 项 | 生成 116 项，含类型/作用域/替换风险/声明者 |
| 注册语义 | “单人槽注册即替换” | 单占同优先级抛错；替换需显式更小 `priority` |
| 元素定位 | `.sectionHeader` 等裸类名 | `data-*` / `[class*="_local"]` / 结构指纹 |
| 鉴权 | `admit({headers})` | `requestRejection(request)` / `admit(request)` |
| 服务清单 | 9 个，无签名 | 40 个常用 + 精确签名 + inspect 查法 |

### 新增（v1 完全没有）

- 全部 5 种基数与 `children` 子槽声明、`inject`/`store`/`locale` 注册位；
- `hoc`（包裹 owner 内容）与 `chain`（选择器竞选）；
- bundle/profile 清单、层序、`engines.dsh`、安装命令；
- 静态 client 半的 `__ModuleLoader__` 构建契约与 esbuild 等价脚本；
- typert 类型化 RPC；
- storageDomain 域与原子写；
- `ctx.settings` 自动表单与 `configure({auto:false})`；
- 会话/工作区数据的读写边界；
- 多插件协作 API（`entriesOfSlot`/`entries`/`subscribe`）；
- `cordis_inspect` 五个 provider 的使用纪律。

### 删除（v1 有、v2 移除）

- “77 个插槽”与任何手写计数；
- 把 Factory 当槽：`conversation.content`、`conversation.user.text`、`conversation.chat.user.content`、`conversation.chat.reasoning.content`、`conversation.approval.card`；
- 不存在的槽：`conversation-queue-dock`、`conversation-todo-dock`；
- 裸哈希类名选择器；
- “单人槽注册即替换”的结论；
- openfilm 特有的 `acp-client.mjs`/`resolveAcpCommand` 细节（改为通用 ACP 边车章节）。

### 待验证（v2 标 ⛔/🟡）

见 [`../COMPAT.md`](../COMPAT.md) §3：客户端 remote 调用表达式、ACP configOptions、`DSH_PERMISSION_MODE`、iframe `frame-ancestors`。

## 3. 具体错误（有证据）

| # | v1 的说法 | 事实 | 证据 |
|---|---|---|---|
| 1 | 单人槽注册即替换 | 同优先级第二次注册**抛错**；替换要更低 `priority` | `ui-slots/src/index.ts:1220` |
| 2 | `conversation.input.model` 是“多” | 实际 `single`，注册会顶掉模型选择器 | live inspect |
| 3 | `conversation.composer.bar` 是“多” | `single` | 同上 |
| 4 | `conversation.content` 是槽 | 是 **Factory** | live inspect `type:"factory"` |
| 5 | `.sectionHeader` 可作选择器 | 构建产物是 `[hash]_sectionHeader` | `tsdown.client.ts:595` |
| 6 | `admit({ headers })` | 接受的是 request；另有 `requestRejection` | `connection/src/rpc.ts:233` |
| 7 | 槽位共 77 | 116 | live inspect |
| 8 | 安装后可用 | reference 全部缺失 | `install-skills.mjs` 只拷 SKILL.md |

## 4. 结论

- **判断类内容**（什么时候替换、怎么留洞、怎么验收）质量高，保留；
- **事实类内容**（槽、API、签名、数量）不可用，改为“生成 + 标注来源”；
- **缺失的是整个分层**：清单/构建/RPC/存储/设置/版本，这些是“能否独立完成插件”的分水岭。

v2 的验收标准因此不是“文档更长”，而是：**另一个 agent 只看 skill 就能选对槽、写对注册、接对通道、装进 profile、并在真机上验证与回退**。
